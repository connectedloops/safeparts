Use releases when you want the CLI or TUI without building the repository. Build from source when you are developing Safeparts or self-hosting the static web app.

## Release downloads

Download release artifacts from GitHub:

- https://github.com/connectedloops/safeparts/releases

Download CLI and TUI archives for Linux, Windows, and macOS. Choose the archive matching your operating system and architecture, and verify it against `SHA256SUMS.txt` before running the binaries.

Historical GUI installers are unsupported. The release history is unchanged; its older desktop downloads are not current recommendations. Existing users should read the [desktop retirement and recovery guide](../desktop/) before changing tools.

Quick check after installing CLI/TUI binaries:

<Steps>
1. Put the binaries on your <span class="token token--mono">PATH</span>.
2. Run <span class="token token--mono">safeparts --help</span>.
3. Run <span class="token token--mono">safeparts-tui --help</span>.
</Steps>

### macOS Gatekeeper

If macOS quarantines a downloaded binary and you trust the release artifact, remove the quarantine attribute:

```bash
xattr -dr com.apple.quarantine /path/to/safeparts-release/
```

## Build Rust binaries from source

Prerequisites:

- Rust stable
- `rustfmt` and `clippy`

```bash
cargo build
cargo test --all-features
```

CI-style lint:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
```

Release binaries:

```bash
cargo build --release -p safeparts -p safeparts_tui
```

## Web app

The web app lives in <span class="token token--mono">web/</span>. It requires a WASM build step.

Prerequisites:

- Bun
- `wasm-pack`, or allow the build script to install it

```bash
cd web
bun install
bun run build:wasm
bun run dev
```

Open [http://localhost:5173](http://localhost:5173).

## Self-host the Web app with Docker

Use Docker when you want to serve Safeparts on infrastructure you control. This route is separate from hosted-provider deployment. It builds WASM, the Web app, and the bilingual help site, then serves only the static output from an unprivileged Nginx image. There is no backend or telemetry, and Secrets and Recovery shares stay in the browser.

From the repository root, build and start the image:

```bash
docker build --pull --tag safeparts-webui --file web/Dockerfile .
docker run --detach --name safeparts-web --publish 8080:8080 safeparts-webui
```

Wait for Docker to report a healthy container, then check the application:

```bash
docker inspect --format '{{.State.Health.Status}}' safeparts-web
curl --fail --silent --show-error http://localhost:8080/healthz >/dev/null
curl --fail --silent --show-error http://localhost:8080/ >/dev/null
curl --fail --silent --show-error http://localhost:8080/help/ >/dev/null
curl --fail --silent --show-error http://localhost:8080/help/ar/ >/dev/null
```

Open [http://localhost:8080](http://localhost:8080). English help is at [http://localhost:8080/help/](http://localhost:8080/help/), and Arabic help is at [http://localhost:8080/help/ar/](http://localhost:8080/help/ar/).

To run the same container route, asset, header, health, and offline-startup checks used by CI:

```bash
bash web/tests/container-smoke.sh
```

Remove the container when you are done:

```bash
docker rm --force safeparts-web
```

## Help site

The help site lives in <span class="token token--mono">web/help/</span> and is served under <span class="token token--mono">/help/</span>.

```bash
cd web/help
bun install
bun run dev
```

Open [http://localhost:4321/help/](http://localhost:4321/help/).

Build the static help site:

```bash
bun run build
```
