استخدم الإصدارات عندما تريد CLI أو TUI دون بناء المستودع. ابن من المصدر عندما تطوّر Safeparts أو تستضيف تطبيق الويب الثابت بنفسك.

## تنزيلات الإصدارات

نزّل مخرجات الإصدار من GitHub:

- https://github.com/connectedloops/safeparts/releases

نزّل أرشيفات CLI وTUI على Linux وWindows وmacOS. اختر الأرشيف المطابق لنظام التشغيل والمعمارية، وتحقق منه باستخدام `SHA256SUMS.txt` قبل تشغيل البرامج.

مثبتات الواجهات الرسومية التاريخية غير مدعومة. يبقى سجل الإصدارات دون تغيير؛ تنزيلات سطح المكتب القديمة ليست توصيات حالية. على المستخدمين الحاليين قراءة [دليل توقف دعم سطح المكتب والاسترداد](../desktop/) قبل تغيير الأدوات.

فحص سريع بعد تثبيت binaries الخاصة بـ CLI/TUI:

<Steps>
1. ضع binaries على <span class="token token--mono" dir="ltr">PATH</span>.
2. شغّل <span class="token token--mono" dir="ltr">safeparts --help</span>.
3. شغّل <span class="token token--mono" dir="ltr">safeparts-tui --help</span>.
</Steps>

### Gatekeeper في macOS

إذا عزل macOS ملفاً تم تنزيله وكنت تثق بمخرج الإصدار، أزل خاصية العزل:

```bash
xattr -dr com.apple.quarantine /path/to/safeparts-release/
```

## بناء binaries من المصدر

المتطلبات:

- Rust stable
- `rustfmt` و`clippy`

```bash
cargo build
cargo test --all-features
```

فحص lint مشابه لـ CI:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
```

Binaries الإصدار:

```bash
cargo build --release -p safeparts -p safeparts_tui
```

## تطبيق الويب

يوجد تطبيق الويب في <span class="token token--mono" dir="ltr">web/</span>. يحتاج إلى خطوة بناء WASM.

المتطلبات:

- Bun
- `wasm-pack`، أو دع script البناء يثبته

```bash
cd web
bun install
bun run build:wasm
bun run dev
```

افتح [http://localhost:5173](http://localhost:5173).

## استضافة تطبيق الويب ذاتيًا عبر Docker

استخدم Docker عندما تريد تشغيل Safeparts على بنية تحتية تديرها أنت. هذا المسار منفصل عن النشر عبر مزوّد استضافة. يبني WASM وتطبيق الويب وموقع المساعدة باللغتين، ثم يخدم الملفات الثابتة فقط من صورة Nginx غير مميّزة الصلاحيات. لا توجد خدمة خلفية أو بيانات قياس عن بُعد، وتبقى الأسرار وحصص الاسترداد داخل المتصفح.

من جذر المستودع، ابنِ الصورة وشغّلها:

```bash
docker build --pull --tag safeparts-webui --file web/Dockerfile .
docker run --detach --name safeparts-web --publish 8080:8080 safeparts-webui
```

انتظر حتى يعرض Docker الحالة `healthy`، ثم تحقّق من التطبيق:

```bash
docker inspect --format '{{.State.Health.Status}}' safeparts-web
curl --fail --silent --show-error http://localhost:8080/healthz >/dev/null
curl --fail --silent --show-error http://localhost:8080/ >/dev/null
curl --fail --silent --show-error http://localhost:8080/help/ >/dev/null
curl --fail --silent --show-error http://localhost:8080/help/ar/ >/dev/null
```

افتح [http://localhost:8080](http://localhost:8080). المساعدة الإنجليزية على [http://localhost:8080/help/](http://localhost:8080/help/)، والعربية على [http://localhost:8080/help/ar/](http://localhost:8080/help/ar/).

لتشغيل اختبارات المسارات والأصول والترويسات والصحة وبدء التشغيل دون اتصال، وهي نفسها المستخدمة في CI:

```bash
bash web/tests/container-smoke.sh
```

احذف الحاوية عند الانتهاء:

```bash
docker rm --force safeparts-web
```

## موقع المساعدة

يوجد موقع المساعدة في <span class="token token--mono" dir="ltr">web/help/</span> ويُخدم تحت <span class="token token--mono" dir="ltr">/help/</span>.

```bash
cd web/help
bun install
bun run dev
```

افتح [http://localhost:4321/help/](http://localhost:4321/help/).

لبناء موقع المساعدة الثابت:

```bash
bun run build
```
