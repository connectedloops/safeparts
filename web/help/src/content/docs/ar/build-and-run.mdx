استخدم الإصدارات عندما تريد CLI أو TUI دون بناء المستودع. ابن من المصدر عندما تطوّر Safeparts أو تستضيف تطبيق الويب الثابت بنفسك.

## تنزيلات الإصدارات

نزّل مخرجات الإصدار من GitHub:

- https://github.com/connectedloops/safeparts/releases

نزّل أرشيفات CLI وTUI على Linux وWindows وmacOS. اختر الأرشيف المطابق لنظام التشغيل والمعمارية، وتحقق منه باستخدام `SHA256SUMS.txt` قبل تشغيل البرامج.

مثبتات الواجهات الرسومية التاريخية غير مدعومة. يبقى سجل الإصدارات دون تغيير؛ تنزيلات سطح المكتب القديمة ليست توصيات حالية. على المستخدمين الحاليين قراءة [دليل توقف دعم سطح المكتب والاسترداد](../desktop/) قبل تغيير الأدوات.

### تحقّق من الأرشيف واستخرجه

نزّل الأرشيف و`SHA256SUMS.txt` من الإصدار الموثوق نفسه إلى مجلد جديد. احسب تجزئة SHA-256 للأرشيف من ذلك المجلد، مع استبدال اسم الملف في المثال:

| النظام وبيئة الأوامر | الأمر |
| --- | --- |
| Linux، Bash | `sha256sum safeparts-release.tar.gz` |
| macOS، Bash | `shasum -a 256 safeparts-release.tar.gz` |
| Windows، PowerShell | `Get-FileHash -Algorithm SHA256 -LiteralPath .\safeparts-release.zip` |

قارن جميع محارف التجزئة (64 محرفاً) مع السطر الخاص باسم الملف نفسه في البيان؛ لا يهم اختلاف حالة الأحرف. **توقّف عند عدم التطابق أو غياب السطر.** تطابق التجزئة يتحقق من التنزيل مقابل البيان، لا من موثوقية ناشره.

بعد التطابق فقط، استخرج الأرشيف إلى مجلد إصدار جديد:

- Linux/macOS: شغّل `mkdir safeparts-release` ثم `tar -xzf safeparts-release.tar.gz -C safeparts-release`.
- Windows PowerShell: شغّل `Expand-Archive -LiteralPath .\safeparts-release.zip -DestinationPath .\safeparts-release`.

مراجع أوامر Windows: [Get-FileHash](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.utility/get-filehash) و[Expand-Archive](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.archive/expand-archive).

<Steps>
1. أضف المجلد المستخرج الذي يحتوي الملفات التنفيذية إلى <span class="token token--mono" dir="ltr">PATH</span> للمستخدم، ثم افتح طرفية جديدة. أو شغّل من ذلك المجلد باستخدام `./safeparts` على Linux/macOS أو `.\safeparts.exe` في PowerShell.
2. شغّل <span class="token token--mono" dir="ltr">safeparts --help</span>؛ يجب أن يعرض طريقة استخدام CLI.
3. في طرفية تفاعلية، شغّل <span class="token token--mono" dir="ltr">safeparts-tui</span>. اضغط <kbd>F1</kbd> للمساعدة و<span dir="ltr"><kbd>Ctrl</kbd>+<kbd>Q</kbd></span> للخروج.
</Steps>

### Gatekeeper في macOS

إذا عزل macOS ملفاً بعد التحقق من الأرشيف أعلاه وكنت تثق بناشره، فأزل خاصية العزل من مجلد الإصدار المستخرج فقط، لا من مجلد التنزيلات كله:

```bash
xattr -dr com.apple.quarantine /path/to/safeparts-release/
```

## بناء الملفات التنفيذية من المصدر

اتبع [متطلبات إعداد المستودع](https://github.com/connectedloops/safeparts/blob/main/docs/dev/onboarding.md) أولاً. تستخدم الأوامر التالية Bash وتبدأ من جذر المستودع؛ وليست أوامر PowerShell. استخدم إصدار Rust المحدد مع `rustfmt` و`clippy`.

```bash
cargo build
cargo test --all-features
```

فحص lint مشابه لـ CI:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
```

الملفات التنفيذية للإصدار:

```bash
cargo build --release -p safeparts -p safeparts_tui
```

## تطبيق الويب

يوجد تطبيق الويب في <span class="token token--mono" dir="ltr">web/</span>. يحتاج إلى خطوة بناء WASM.

أكمل [إعداد المستودع](https://github.com/connectedloops/safeparts/blob/main/docs/dev/onboarding.md) لتثبيت Rust/rustup وBun وNode وBash. قد يثبّت برنامج بناء WASM إصداري `wasm-pack` و`wasm-bindgen-cli` المحددين أو يستبدلهما، وينزّل هدف WASM.

من جذر المستودع:

```bash
cd web
bun install --frozen-lockfile
bun run build:wasm
bun run dev
```

افتح [http://localhost:5173](http://localhost:5173).

## استضافة تطبيق الويب ذاتيًا عبر Docker

استخدم Docker عندما تريد تشغيل Safeparts على بنية تحتية تديرها أنت. هذا المسار منفصل عن النشر عبر مزوّد استضافة. يبني WASM وتطبيق الويب وموقع المساعدة باللغتين، ثم يخدم الملفات الثابتة فقط من صورة Nginx غير مميّزة الصلاحيات. لا توجد خدمة خلفية أو بيانات قياس عن بُعد، وتبقى الأسرار وحصص الاسترداد داخل المتصفح.

من جذر المستودع، ابنِ الصورة وشغّلها:

```bash
docker build --pull --tag safeparts-webui --file web/Dockerfile .
docker run --detach --name safeparts-web --publish 8080:8080 safeparts-webui
```

انتظر حتى يعرض Docker الحالة `healthy`، ثم تحقّق من التطبيق:

```bash
docker inspect --format '{{.State.Health.Status}}' safeparts-web
curl --fail --silent --show-error http://localhost:8080/healthz >/dev/null
curl --fail --silent --show-error http://localhost:8080/ >/dev/null
curl --fail --silent --show-error http://localhost:8080/help/ >/dev/null
curl --fail --silent --show-error http://localhost:8080/help/ar/ >/dev/null
```

افتح [http://localhost:8080](http://localhost:8080). المساعدة الإنجليزية على [http://localhost:8080/help/](http://localhost:8080/help/)، والعربية على [http://localhost:8080/help/ar/](http://localhost:8080/help/ar/).

لتشغيل اختبارات المسارات والأصول والترويسات والصحة وبدء التشغيل دون اتصال، وهي نفسها المستخدمة في CI:

```bash
bash web/tests/container-smoke.sh
```

احذف الحاوية عند الانتهاء:

```bash
docker rm --force safeparts-web
```

## موقع المساعدة

يوجد موقع المساعدة في <span class="token token--mono" dir="ltr">web/help/</span> ويُخدم تحت <span class="token token--mono" dir="ltr">/help/</span>.

ابدأ بطرفية جديدة في جذر المستودع بعد تثبيت أدوات الإعداد:

```bash
cd web/help
bun install --frozen-lockfile
bun run dev
```

افتح [http://localhost:4321/help/](http://localhost:4321/help/).

لبناء موقع المساعدة الثابت:

```bash
bun run build
```

يبني هذا موقع المساعدة فقط في `web/dist/help/`. لبناء التطبيق والمساعدة باللغتين معاً، شغّل `mise run web:build:site` من جذر المستودع. لا تشغّل بناء التطبيق المنفرد بعد ذلك لأنه يحذف مخرجات المساعدة.
